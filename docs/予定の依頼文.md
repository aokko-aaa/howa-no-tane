claude.ai/code の予定の設定で、**間隔を「毎週」に変え、依頼文を下の枠の中身に差し替えて**ください。
（この文書はアプリからは読まれません。貼り付けるための控えです。）

```
真宗大谷派の住職が使う「法話のタネ」というアプリの、話の案を増やす作業です。週に一度走ります。人は見ていません。自分で最後まで進めて、公開してください。

今回からの中心は「書きっぱなしにしない」ことです。前の回の案を住職が読んで書いた感想を最初に受け取り、それを書き方に活かしてから書きます。

## 0. 作業記録を残す（飛ばさない）

/home/user/howa-no-tane/docs/走った記録.md に、節を一つ終えるたびにその場で追記し、そのたびに claude/routine-log ブランチへ push すること。各行は「何時何分・何をした・通ったか落ちたか・落ちたなら実際に出た文字」。推測を書かない。案が一件も書けなかった回でも、この記録だけは必ず push する。

## 1. リポジトリを用意する

リポジトリが無ければ add_repo で aokko-aaa/howa-no-tane を足す。そのあと必ず：

git -C /home/user/howa-no-tane fetch --unshallow || true
git -C /home/user/howa-no-tane config remote.origin.fetch '+refs/heads/*:refs/remotes/origin/*'
git -C /home/user/howa-no-tane fetch origin

main を origin/main に合わせてから npm ci を通す。

## 2. 決まりを読む

CLAUDE.md を最初に読む。とくに「人がいないところで走るとき」「感想を聞いて、次に活かす」「このアプリの中にいる人」の節。

## 3. 感想を受け取る（書く前に）

1. docs/聞いた感想.md の「（感想あり）」の節を読む
2. 次から守ることを docs/書き方の覚え.md に一行ずつ移す（どの案の感想からかを添える。感想に書かれていないことを推し量って足さない）。移し終えた節の見出しは「（感想あり・覚えに移した）」にする
3. 「ここを直して」とある案は、その指摘の範囲だけ直す候補にする
4. 「次はこういう案がほしい」とあれば、それを今回書くものの先頭にする
5. 「（感想待ち）」の案が9件を超えていたら、今回は新しく書かない。記録を push し、感想をお願いする通知だけ送って終える

## 4. 書く（一度に3件まで）

docs/書き方の覚え.md を読んでから書く。何を書くかは CLAUDE.md の順（感想の希望 → 通夜・葬儀の五分の案 → 案の無い仏教語 → 人物のまわり → お勤めの一節）。足すときは src/data/concepts.ts に同じ語が無いか見る。欄の使い分け（origin・now・gap・caution）は CLAUDE.md の表で確かめる。

## 5. 係に回す

subagent_type: "tenkyo-checker" は通らない。general-purpose を二つ同時に立て、それぞれ冒頭でこう指示する：

- 典拠係：「まず /home/user/howa-no-tane/.claude/agents/tenkyo-checker.md を読んで、そこに書かれた役・判定基準・出力形式にそのまま従ってください」
- 聞き手係：「まず /home/user/howa-no-tane/.claude/agents/kikite-checker.md を読んで、そこに書かれた役・判定基準・出力形式にそのまま従ってください。あわせて /home/user/howa-no-tane/docs/書き方の覚え.md も読み、住職の感想から来た覚えに反していないかも見てください」

「疑わしい」と言われた典拠はその場で外す。残りが0件になっても、それは正しい結果。何を書いて係が何と言ったかを記録に書いて終える。

## 6. 通して、押す

1. docs/確かめること.md に、典拠係の「人が確かめる一覧」を追記
2. docs/聞いた感想.md の末尾に、今回入れた案を「（感想待ち）」で足す（題・id・芯・一歩か結び・空の「感想：」）
3. npx tsc -b --noEmit → npm test → npm run build
4. 日本語でコミットして git push -u origin main
5. git rev-parse HEAD と git ls-remote origin refs/heads/main が同じかを実物で確かめる。違えば、出たエラーをそのまま記録に写して push

## 7. 知らせる

PushNotification で必ず知らせる。先頭の一文は「今週の案：〈題〉／〈題〉／〈題〉。感想を docs/聞いた感想.md に一言ください」。そのあとに、受け取った感想から覚えに移したこと（無ければ「感想はまだありませんでした」）と、外した案があればその理由。書けなかった回は、どの段で、どのコマンドが、どう落ちたかを書く。

量より、間違ったことを語らせないことのほうが大事です。docs/走った記録.md の push だけは、どんな回でも必ず済ませてから終えてください。
```
