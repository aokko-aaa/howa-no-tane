つなぎ目をどう安全にするかが、この設計の中心です。

## 2. 根っこ：安全が「つなぎ目」に住んでいる

この二か月に見つかった不具合は、ばらばらに見えて全部同じ形をしています。

**素材そのものは正しい。切り口そのものも正しい。掛け合わせたところで危なくなる。**

そして掛け合わせを見ている人が、どこにもいません。素材を書く人は切り口を見ずに書き、
切り口を書いた人は、まだ書かれていない素材を想像して書いています。

### 実際に起きたこと

**「成仏」の `question` 欄**（2026-11-20）

欄に書いたのは `'あの人は、いま、どうなっているのだろう'`。素材としては何も間違っていません。
ところが構成「問い」（`src/lib/structure.ts`）は、この欄をこう使います。

> ② 問い（**声に出す**）
> ③ 間（答えを言わない。二拍おく）
> ⑥ 問いに戻す ——**答えは言いません。持ったまま帰っていただくのが、今日のおみやげです。**

通夜の席で、ご遺族がいちばん怖くて口に出せずにいる問いを、住職が代わりに二度声に出して、
二度とも答えずに帰す形になります。しかもこの語にかぎっては、真宗は答えを持っている。

**欄を見ても分かりません。切り口を見ても分かりません。**

**`caution` が見えるかどうか**（2026-09-23 と 11-20 の二度、取り違えた）

「どこにも出ない」と思い込んで設計し、`CLAUDE.md` にもそう書いた。実際は
`DictView.tsx:180` と `generate.ts:1032` で**画面に出る**。出ないのは検索だけ。

**`origin` が出典欄に並ぶ**（2026-09-23 に気づいた）

`generate.ts:1031` が `sources.push(\`${word}：仏教語（${origin}）\`)` としている。
つまり `origin` の不確かさは、説明の誤りではなく**画面に出る偽の典拠**になる。
事典の語釈のつもりで書いていた。

**「成仏」が検索で0件**（2026-11-20）

アプリ全体で `shinshu/manners.ts` の「避ける言い方」一箇所にしか無かった。
`SOURCE_KINDS = ['concept','phrase','figure']`（`situations.ts:37`）に manner が入らず、
辞書（`DictView`）は開いている棚の中しか探さない。**二度検索を直して、二度とも漏れた。**

**大谷派が使わない語を、大谷派モードで前に出していた**（2026-09-23）

「開眼」に `tradition: 'shinshu'` を付けた。`TRADITION_BONUS`（`generate.ts:655`）は
otani で shinshu に **+4**。大谷派が使わない語が、大谷派モードで優先的に出る設定になっていた。

## 3. 破綻の一覧

### 破綻一：決まりと実装が逆を向いている

`CLAUDE.md` にはこう書いてあります。

> 素材を組み合わせて文章を作らない
> 「だからこうつながります」と機械が言わない

ところが `structure.ts` は、ご遺族の自責を読み上げたあとに自分でこう続けます。

> **それで片づくなら、この問いはとっくに消えています。**

やらないと決めたことを、1169行かけてやっている。
**生成を残すなら、この決まりのほうを書き直さなければいけません。**
「組み立てない」ではなく「**どこまでなら組み立てるか**」を決める。

### 破綻二：切り口が席を知らない

いちばん大きい。

```
export type Angle = {
  id, name, tradition?, aim, needs, kojitsuke
}
```

**`Angle` に席の欄がありません。** 20の切り口は、どの席で鳴らしてよいかを一度も問われていない。
「問い」の構成（答えを伏せて帰す）も、「こじつけですが」の構成も、
通夜の席で法話会とまったく同じように選ばれます。

素材の側も同じで、`avoidScenes` を持つ型は **`Modern` ただ一つ**（`types.ts:165`）、
使っているのは **`generate.ts:762` の一箇所だけ**。
`Concept` にも `Word` にも `Figure` にも無い。

住職のいちばんの要望は「通夜・葬儀で使えること」でした。
**その席を、仕組みはほとんど見ていません。** 席を外す手立ては `caution` という散文一行で、
誰も強制していない。

### 破綻三：欄の行き先が、型に書かれていない

どの欄が声に出て、どの欄が手元に残り、どの欄が出典欄に並ぶか。
いまそれは `generate.ts` の1169行の中に散らばっていて、型を見ても分かりません。

私は二か月のあいだに三回取り違えました（`caution`・`origin`・`question`）。
**コードを見ながらでも頭に入らない構造です。** 住職にも、毎週走る無人のセッションにも、入りません。

### 破綻四：主が「語」ではなく「棚」

「成仏」は manners にしか無かった。
「縁起」「主人公」「四苦八苦」「自業自得」は words と concepts の両方にあって、
組み合わせの題が「**こじつけですが —「縁起」と縁起**」になっていた。

**「この語について分かっていること全部」という単位がどこにもありません。**
だから検索が棚ごとになり、重複が見つからず、二度直しても漏れる。

### 破綻五：辞典と案が別勘定

毎週の通知にも画面にも、棚の件数が出ていなかった。
だから二か月、辞典がまったく増えていないことに誰も気づかなかった。

## 4. 設計の案

### A. 席を、素材にも切り口にも持たせる（最優先）

```
Angle に scenes: SceneId[] を足す（必須。省略不可にする）
すべての素材型に scenes?: SceneId[] / avoidScenes?: SceneId[] を足す
生成は、席に合わない切り口・素材を「好み」ではなく「候補から除く」
```

いまの `TRADITION_BONUS` のような**点数**ではなく、**可否**にすること。
点数だと、ほかの条件が強ければ通ってしまいます（「開眼」がそうでした）。

### B. 欄の行き先を、型で表す

欄ごとに行き先の札を付ける。

```
声に出す  … 席で読み上げられる。前置きなしで耳に入って分かる文でなければならない
出典     … 案の出典欄に並ぶ。言い切れないことを書いてはならない
手元     … 語り手のメモ。聞き手には届かない
```

そのうえで、**札と実装が食い違っていないかを試験で押さえる。**
`generate.test.ts:558`（声に出す本文に、大谷派で避ける言い方が混ざらない）が
すでにその一例で、今日それが私の下書きを実際に止めました。あれを一般化する。

### C. 切り口が、欄に何をするかを宣言する

```
「問い」の構成：question を二度読み上げ、答えを与えずに終える
「こじつけ」の構成：word と concept を並べ、無理を承知でつなぐ
「落差」の構成：misread を「世間では〜」で括り、pivot で返す
```

これを型に書いて、**素材を書く画面・指示書の側に出す。**
欄を埋める人が、その欄がどう鳴るかを見ながら書けるようにする。
「成仏」の `question` は、これがあれば書く前に止まっていました。

### D. 語を主にする

棚（ことば／仏教語／言い回し）を**表示の都合**に落として、
「語」を一つの単位にする。一つの語が、日常語としての顔・仏教語としての顔・
席での言い換えの注意を、まとめて持てるようにする。

検索は語を見る。棚は見ない。

### E. 総当たりで押さえる

`combine.sweep.test.ts` が一件だけありますが、見ているのは組み直しだけです。

```
すべての素材 × すべての切り口 × すべての席 を回して、
声に出す本文を、席の禁則に当てる
```

禁則は、係の指摘が出るたびに**一行ずつ足していく**。今日の分だけでも：

- 大谷派で避ける言い方（既にある）
- ご遺族の内心を「世間では」で括らない
- 「心配は要らない」と読める形にしない
- 今日の一歩を、できなかったという残り方をするものにしない
- 席についての観察（「いちばん多い問い」）を、読み上げる欄に置かない

**これがこの作り直しのいちばんの肝です。** 人が毎回気をつけるのではなく、
一度見つけた危険を、二度と通さない形で貯める。

### F. 棚の件数を、画面と通知に出す

増えているかどうかが、見れば分かるようにする。

## 5. 順番

1. **B（欄の行き先を型に）** と **E（総当たりの禁則）** を先に。
   これは今あるデータを一行も変えずにできて、以後の間違いを止めます。
2. **A（席を可否にする）**。素材に席を書き足す作業が要りますが、
   住職のいちばんの要望に直に効きます。
3. **C（切り口の宣言）**。A と B が済んでいれば、書くのは宣言だけです。
4. **D（語を主にする）**。いちばん大きい工事。1〜3 のあとに。
5. **F** はいつでも。

## 6. この診断で決めていないこと

- **20の切り口を減らすかどうか。** 減らすべきだと思いますが、どれを残すかは、
  住職が実際に使って決めることです。E の総当たりを先に通せば、
  「どの席でも禁則に当たる切り口」が数字で出ます。そこから相談する。
- **「組み立てない」という決まりの書き直し方。** 生成を残すと決めた以上、
  `CLAUDE.md` の該当箇所は現状と食い違っています。どこまでなら機械が書いてよいかは、
  住職の言葉と機械の言葉の境目をどこに引くかの話なので、人が決めることです。
