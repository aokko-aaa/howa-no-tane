# 法話の種

日常の気持ちを入口に、法話の切り口をまとめて出す下ごしらえ帳。
**話したいことから、いまの情景を引っ張り出す**ための引き出しでもある。

**公開先: https://aokko-aaa.github.io/howa-no-tane/**

## つくりの考え方

教義から降りていくのではなく、**一般の人が実際に立ち止まる場面**（既読がつかない、同級生の新築、免許返納…）から始めて、そこから仏教へ渡す。
同じ気持ちから **21通りの切り口** を回して出すので、「その話はもう何度も聞いた」となりにくい入口を探せる。

### 今の暮らしからのたとえ

経典の喩えは、置き換えの一手間がいる。「琴の弦を張りすぎても」と言われて、琴を触ったことのある人が何人いるか。
`src/data/parables.ts` は、**出典のない見立て**を18種。スマホの充電、通知バッジ、解約し忘れたサブスク、
ルートを再検索します、たたんだそばから崩される、星ひとつのレビュー、入力中…のまま消える。
切り口〈今のたとえで〉は、ここから入って教えへ渡す。

出典がないことは隠さない。`source` は「現代のたとえ（出典はありません）」、
カードの「語る前に確認」には毎回「経典の話ではありません」が出る。
**通夜・葬儀のあと、死別・いのちの話（大きさ3）では候補から外す。** 場に合わない。
ひと回しの中でも半分まで。全部これになると軽くなる。

### 話題（素材どうしをつなぐ層）

気持ちのタグだけでつなぐと荒すぎる。〈自己嫌悪〉という一語で
「鏡に映った自分」と「他力本願」と「解約し忘れたサブスク」が同じ話にされ、
入口・問い・たとえが三つ別々の話になっていた。

`src/data/topics.ts` に17の話題。たより／終わりのない仕事／先延ばし／人と比べる／直らない自分／
人からどう見られるか／報われない／時間に追われる／怒り／手放せない／役割と自分／死と別れ／
お金・損得／あたりまえ／人づきあい／節目／分からない。
仏教語70・入口56・たとえ58・人物24の**全208件**に付けてある。

言葉を選んだあと、**その言葉と同じ話題を向いた入口・たとえ・人物**から引く。
ただし順序は変えない——**選んだ気持ちが先、話題はその中での好み**。
話題で絞ったせいで気持ちから外れるようなら、話題のほうを譲る。
（絞り込みにしたら、選んだ気持ちから外れた入口が出てテストが22件落ちた）

ひと回し6案で同じ話題の入口を使い切ることがあるので、揃う割合は約8割。
尽きたときに話題を外すのは正しい。同じ入口を二度出すほうが悪い。

### 話の大きさ

入口の場面と、返す仏教語の**桁が合っていないと、こじつけ以前に届かない**。
「家事子育てに追われて自分とは何かがわからなくなる」に往生や臨終の話を返しても、壮大すぎる。
仏教語は三段階の大きさを持つ。

| | |
| --- | --- |
| **1 暮らしの寸法** | 足元・言葉づかい・段取り（照顧脚下、中道、第二の矢、無財の七施…） |
| **2 人生の局面** | 関係・立場・変わり目（煩悩具足の凡夫、諸行無常、報恩、聞法…） |
| **3 いのち・救い** | 語るのに場が要る（本願、南無阿弥陀仏、現生正定聚、還相回向…） |

既定の〈おまかせ〉は、**書かれた文 → 場面 → 気持ち** の順に見て決める。
「家事」「子育て」「職場」なら1へ、「余命」「看取」「通夜」なら3へ。通夜・葬儀のあとは場のほうが3を決める。
〈暮らしの寸法で〉〈いのちの話で〉と手で指定もできる。

大きさは**絞り込みではなく好み**として効かせる。
書かれた文や選んだ気持ちに当たっている言葉を、桁が違うからといって外さない（順序は
文の一致 ＞ 気持ちの一致 ＞ 大きさ ＞ 宗派）。
ひと回しの中で同じ大きさが偏らないよう、上限も置いてある。
真宗の根幹語はどれも大きいので、これが無いと大谷派モードの6案が全部「いのちの話」になる。

既定は **真宗大谷派を優先**（`tradition: 'otani'`）。本願・他力・聞法・報恩を軸に、真宗の切り口（お聖教の一句／御文／歎異抄／私の上に聞く／誤用から入る／報恩講）を先に回し、禅語の素材は後ろへ下げる。結びにはお念仏の一句が添い、語り手向けメモに大谷派の言い回しの注意が入る。
「宗派を問わない」に切り替えると、真宗固有の切り口を外して共通の素材だけで組む。

素材はすべてアプリの中に持っている。外部APIもサーバーも使わない（入力も保存も端末のブラウザの中だけ）。

## 三つの入り方

| タブ | 誰が | 何をする |
| --- | --- | --- |
| **つくる** | お寺の方 | **気持ちを押すと、その場で6通り出る**。場面・宗派・こじつけ度・月は〈詳しい設定〉に畳んであり、既定のままで使える。〈素材を指定して探す〉で「この言葉で」「この一句で」と名指しもできる |
| **くらし** | どなたでも | 開くと〈今日の一つ〉に、毎日使っている言葉の出どころが出る（大丈夫・我慢・億劫…）。その下で、三つ選ぶと今の気持ちに合う話がひとつ出る |
| **話したいことから** | 僧侶 | 話したいことを選ぶと、それに近い**いまの情景**が並ぶ。文章は組み立てない |
| **ネタ帳 / ことば** | 共通 | 保存とメモ、仏教語・お聖教・日常語・喩え話・人の小ネタ・大谷派の言い回しを引く |

### 気持ちの掘り下げについて

「イライラする」だけでは素材の当てようがないので、選ぶと一段下が開く。

```
イライラする　なんで？
　思い通りにいかない／疲れている・体調がよくない／あの人が許せない／自分に腹が立っている
不安でたまらない　何が？
　将来のこと／お金のこと／健康・病気のこと／家族のこと／人からどう見られるか
```

理由は、気持ちを足し込む（例：お金のこと→ okane）と同時に、
とくに当たりやすい仏教語を前に出す（例：あの人が許せない→ 怨みは怨みによって止まず・忍辱）。
選ばなくても出る。選ぶと、ひとことに「イライラする（あの人が許せない）」と出る。

### たどる（チャート）について

きもち → ことがら → どうしたい、の三択で一つの読み物にたどり着く。
出力は法話の下書きではなく、そのまま読める文章（`src/lib/reading.ts`）。
一つ目の「きもち」を二つ目より強く効かせて、悲しみの相談に子育ての場面が出るようなズレを避けている。

## 話したいことから（`src/lib/situations.ts`）

向きが逆の使い方。**僧侶が話したいことを選び、それに結びつく現代の情景を引っ張り出す。**

- **この言葉で話す**（仏教語70）
- **この一節で話す**（お聖教26）
- **この人物の話をしたい**（人物24）

選ぶと、まず〈**この言葉でできる話**〉が出る。それから、近い情景が束に分かれて並ぶ。

### 話の案（`src/data/takes.ts`）

**「南無阿弥陀仏でどういう話ができるか」に答えるものは、組み合わせからは出てこない。**
素材をいくら並べても「材料の一覧」にしかならない。一案ずつ手で書くしかない。

```
案／お願いと、呼び声
手を合わせるとき、私たちはたいてい「お願いします」と言っている。
けれども帰命とは、本願招喚の勅命——向こうから呼ばれている声のほう。
称えるのは、頼むことではなく、答えること。
  入口：初詣の列／合格祈願のお守り／賽銭を入れる手
  一歩：今日、手を合わせたとき、頼みごとを言わずにただ称えてみる
  典拠：「帰命は本願招喚の勅命なり」（『教行信証』行巻・六字釈）
```

一案は **題・芯（二、三文）・入口（複数）・一歩・典拠・語る前に確認**。
入口に内蔵の場面を結んであれば、語り出しの一文も引ける。

いまある案は **39件／10語**（南無阿弥陀仏5・本願4・他力4・煩悩具足の凡夫4・報恩4・
摂取不捨4・諸行無常4・聞法4・お浄土3・平生業成3）。
一覧では〈話の案 5〉のように件数が出て、案のあるものが先に並ぶ。
案の無い言葉は、下の情景から自分で組み立てる。

書くときの決まりは `takes.ts` の冒頭にある。**典拠は確かなものだけ。**
領解（受け取り方）は典拠ではなく「語る前に確認」に書く。

### 情景の一覧

近さで束に分けて並ぶ。

```
南無阿弥陀仏                                    ［選び直す］
答えている問い：手を合わせて、何をお願いすればいいのか
─────────────────────────────── ↑ 上に留まる

近いところ  5件  話題が二つ以上重なっています

  病室の窓                                  ひらく
  同じ景色を見る日が、こんなに長いとは思っていなかった。

  健康診断の再検査通知                        ひらく
  まだ何も決まっていないのに、先の話ばかり考えてしまう。

すこし離れる  13件  話題が一つ重なっています
  （3件だけ出して、あとは畳む）
```

一覧は**場面の名と「そこで思っていること」だけ**。ひらくと語り出し・**どこで重なるか**・ボタンが出る。

### どこで重なるか

「重なっています：たよる」とラベルの名前を出すだけでは、
**なぜその場面でその言葉が要るのか**が分からない。集合の積を取っただけで、思考が無い。

全組み合わせ（仏教語70×場面56＝**3,920通り**）は書けないので、**話題を経由する**。
17の話題それぞれに「場面の側で起きていること」と「言葉の側が言っていること」を持たせた（17×2＝34行）。

```
南無阿弥陀仏 × 病室の窓

〈たよる・ひとりで抱える〉
  この場面では  ひとりで抱えていて、誰にも頼めないでいる。
  この言葉は    あてにしてよいものが、こちらの求めより先に来ている。

〈分からない・迷い〉
  この場面では  調べても聞いても、答えの出ない問いを抱えている。
  この言葉は    答えを出すのではなく、問いのまま抱えていられる形を示す。
```

**最後のひと渡しは書かない。** 両側を並べて、あいだは空けておく。そこが語り手の仕事。
下ごしらえの用紙にも、AIへの指示書にも、同じものが入る。

画面の作りで気をつけたこと。

- **十二件すべてを開いて並べない。** どれも同じ重さになって選べなくなる
- **並び順だけでは近さが見えない。** 束に分けて見出しで示す
- **気持ちの札を一覧に出さない。** 「穏やか・満たされている」が病室の窓に付くと、
  合う合わないの判断を邪魔するだけ。ひらいたときに小さく出す
- **ボタンはひらいた一件にだけ。** 十二件ぶん並べると三十六個になる
- 話したいことは上に留めておく。何を探していたのか見失わないように

**ここで文章は組み立てない。** 言うのは「この情景が、その言葉の近くにあります」までで、
「だからこうつながります」とは言わない。組み合わせで文章を作ると、
断片どうしが互いを知らないぶん、必ずどこかで筋が通らなくなる（`## つくる` の項を参照）。
両側を並べて、重なっている話題と気持ちを隠さず出し、つなぐのは語り手にまかせる。

〈下ごしらえの用紙をコピー〉は、両側を並べてつなぎ目を［　］で空けた紙を出す。

入口56件には `omoi`（その場面で人が内心思っていること）がある。
場面そのものより、そこで動いている心のほうが、話したいこととの手がかりになる。

## 出力

- **法事・月参り・法話会**：入口 → ひっかかり → 仏教のことば → 視座のズレ → 落とし込み → 結び ＋ 語り手向けの演出メモ
- **掲示板・SNS**：一行の案3つ ＋ 短文 ＋ 聞かれたときの仕込み

### 問いから始める（既定の形）

法話は、答えから始めると説教になる。だから仏教語70種は、
**「この言葉が答えている問い」を一行ずつ持っている**（`Concept.question`）。
問いは聴き手の言葉で書く。教義の語は使わない。

| 仏教語 | 答えている問い |
| --- | --- |
| 無財の七施 | 何も持っていない私に、できることがあるのか |
| 主人公 | 役割ばかりで、自分はどこにいるのか |
| 中道 | どこまでがんばればいいのか |
| 煩悩具足の凡夫 | 直らない自分は、だめなのか |
| 本願 | 私の願いは、いつも途中で折れる。それでも願っていいのか |

カードの既定は〈**問い**〉の形。

```
① その場面           家事子育てに追われて、自分とは何かがわからなくなる。
② 問い（声に出す）    ——どこまでがんばればいいのか。
③ 間（声に出さない）  ここで答えを言わない。二拍おく。
④ 世間の答え          「中道＝ほどほど」と理解されている。
                      それで片づくなら、この問いはとっくに消えています。
⑤ 手がかり            中道（ちゅうどう）。張りすぎても、ゆるめすぎても、音は鳴らない。
⑥ 問いに戻す          もう一度うかがいます。どこまでがんばればいいのか。
                      答えは言いません。［ご自身ならどう答えるか、一行だけ］
⑦ 今日の一歩          今の自分の弦が「張りすぎ」か「ゆるみすぎ」か、どちらかを選ぶ。
```

守るのは四つ。**②で答えを言わない**／**結びは答えではなく問いを返す**／
**一案に問いは一つ**／**〈間〉を欄として立てる**。
黙る場所が書かれていないと、語り手はそのまま答えへ進んでしまう。

カードは五つの形で読める。**問い**（既定）／**筋道**（要点の箇条書き）／**話す形**（語り口の原稿）／
**起承転結**（場面→そこで起きていること→ひっくり返す→暮らしへ戻す）／
**PREP**（言いたいこと→なぜ→たとえば→もう一度）。
素材は変えず、並べ方と言い方だけを型に合わせる（`src/lib/structure.ts`）。
コピーは、いま見ている形で取れる。

PREPは説得の型なので、問いから入る話とは噛み合わない。研修や講義向けに残してある。

カードは**要点（箇条書き）**で出る。素材を名詞で並べてあるので、6案を見比べるときに読み下さなくてよい。
〈話す形〉に切り替えると、そのまま語れる文章になる。

入口の場面と切り口は**決め打ちではない**。カードの〈入口を変える〉〈切り口を変える〉で、
ことば・喩え・一句はそのままに、そこだけ次の候補に入れ替わる（押すたびに候補を順に回る）。
入口は「ご自身の一件に差し替え可」と明記してある。誰かの体験談をなぞる形にしないため。

コピーは3種類。**要点**（箇条書きと出典）／**下書き**（見出し・出典・演出メモ込み、推敲用）／
**通し原稿**（そのまま読める形。語り手向けメモは外れる）。

### 組み合わせて一本にする

気になった案に〈組む〉を入れて二つ以上えらぶと、一本の話に組み直せる（`src/lib/combine.ts`）。

**素材を並べるだけでは筋が通らない。** 話の筋は一本しか通らないので、集めた仏教語を横に並べず、役をふる。

| 役 | どうするか |
| --- | --- |
| **軸** | 今日の話はこの一語のこと。入口から結びまで、これで通す |
| **受け** | 軸だけでは届かないところへ渡すために、一度だけ出す |
| **控え** | 残りは語らない。演出メモに回す（素材としては消さない） |

軸は、集めた言葉のうち**ほかの言葉といちばん気持ちが重なっているもの**を選ぶ。
端に寄った言葉を軸にすると、ほかが全部ぶら下がらない。受けは、軸にいちばん近いもの。

見出しは素材の種類名（「入口」「ひっかかり」）ではなく、**話のどこにいるか**で付ける。
上から順に読めば、そのまま喋れる並びになっている。

```
お聖教の一句
はじまり — この場面から
そこで起きていること
今日の一語 —「◯◯」
たとえに／人の話に／ことばのもとは — ◯◯
ここが山 — 一語では届かない        ← 背骨
もう一語 —「◯◯」
自分の言葉で（ここだけは埋めてください）
今日の一歩
結び
演出メモ（語り手向け・声に出さない）
```

**〈ここが山〉がこの組み直しの背骨。**
「——ここまでが『軸』の話です。ただ、言葉として分かっても、あの場面に立てば、また同じところでつまずきます」
と一段入れてから受けを出す。ここを抜くと、二語がただ並んだだけになる。
結びは軸の一語に戻る。

**語り手への指示は、本文にも筋道にも出さない。** 「結びは軸に戻す」「尺が足りなければここを落とす」
「この喩えの使いどころ」は全部、演出メモにだけ書く。筋道に混ざると、何の話か読めなくなる。
筋道の各行は「場面：」「今日の一語：」のように頭がつき、カードではその頭だけ小さく立つ。

入口と喩えは、**その言葉と組んで出てきたもの**をそのまま使う（生成時に気持ちを合わせてあるため）。
自分で書いた一件があれば、それが入口。
演出メモには、軸・控え・**尺が足りないときの落とし方**（受けの段をまるごと落とせば軸だけで一本になる）が入る。

つなぎ目の一行だけは機械が書かない。**重なるところ**は［　］のまま残してある。
ここを埋めたところに、その人の色が出る。「私にはまだ結びついていません」でも成り立つ。
出典と「語る前に確認」は、もとの案から全部引き継ぐ。

**ネタ帳でも同じことができる。** 日をまたいで溜めたもの同士を組み直せる。
組んだものをネタ帳に入れれば、それをまた次の材料にできる。
このとき素材は落ちない（`sourceMaterials` に、もとの案の素材をそのまま持たせてある）。

## AIに渡して成形してもらう（`src/lib/brief.ts`）

このアプリは文章を組み立てない。代わりに、**素材と守ってほしいことを一枚にまとめて**書き出す。
ChatGPTやClaudeに貼れば下書きが返る。書くのは向こう側、素材と縛りを渡すのがこちらの役目。

ネタ帳の〈AIに渡す〉から。一件ずつ／〈組む〉で選んだぶん／ネタ帳ぜんぶ。
組み立て（問いから・起承転結・まかせる）、長さ（掲示板／3・5・10分）、
大谷派の作法に合わせるかを選べる。

渡すもの：仏教語とその**答えている問い**・世間での受け取り・ズレ・今日の一歩・出典／
お聖教の一節／人物／たとえ／日常語のもと／情景と**そこで人が思っていること**／
**語り手のメモ**（いちばん大事なものとして渡す）／出典／語る前に確認。
語り手向けの演出メモは渡さない（AIが読むものではない）。

**いちばん大事なのは、作らせないための縛り。**
仏教の素材をAIに渡すと、もっともらしい出典や逸話をこしらえる。指示書には必ず、

- 出典は、書き出した範囲だけを使う
- 書かれていない事実（年号・人物・逸話・引用）を作らない
- 最後に、自信のないところを「確かめてほしいところ」として挙げる

が入る（テストで縛ってある）。それでもAIは作り話を混ぜるので、
**返ってきた引用は語る前に原典で確かめること。** 画面にもそう出している。

## 評価をためる

**アプリは学習しない。** 中にモデルもサーバーも無い静的なページなので、学習ループを回す場所がない。
できるのは、評価を端末に溜めて書き出すところまで。直すのは人がやる（`src/lib/ratings.ts`）。

カードの下に〈◎ 使える〉〈△ ちがう〉。△には**どこが？**（言葉／問い／たとえ／入口／全体）と一言を添えられる。
◎△だけでは何を直せばいいか分からないので、押した時点で**その案が何でできていたか**を一緒に写し取る。
仏教語・その言葉が答えている問い・話の大きさ・切り口・たとえとその種類・人物・日常語・一句・入口、
そして書いた文・気持ち・場面・教え・話の大きさの設定まで。あとから案を復元できなくても、これがあれば直せる。

ネタ帳タブの〈評価を書き出す〉でMarkdownがコピーされる。△が出た素材の集計表と、一件ずつの記録。

**評価をアプリの出し方に反映させてはいない。** ひとりで試す規模（数十件）では、
仏教語70種 × 切り口21種に対して統計にならず、たまたま低く付いた言葉が消えるだけになる。
「飽和の切り口を探す」という狙いと逆に、候補が痩せていく。
出さない言葉を決めたいなら、統計ではなく明示の指示にするほうがよい。

## 出典の扱い

出典は通称で記している。**人前で語る前に原典を確認すること**を前提にしている。
語源や逸話に諸説あるもの（諦める、油断、白隠「そうか」、妙好人の逸話など）はカードの「語る前に確認」に出る。

真宗大谷派の作法・呼び方（位牌と法名軸、焼香の回数、御文と御文章、盆の勤め方、帰敬式の案内など）は
**地域と寺によって実際の扱いに幅がある**。アプリは由来として示すだけなので、自坊の実際に合わせて語ること。
「ことば」タブの〈大谷派の言い回し〉は、門徒さんの習慣を否定するための材料ではない。

## 開発

```sh
npm install
npm run dev        # 開発サーバー
npm test           # データとネタ生成のテスト
npm run typecheck
npm run build      # dist/ に静的ファイル
```

## デプロイ

`main` に push すると GitHub Actions（`.github/workflows/deploy.yml`）が
typecheck → test → build を通し、`dist/` を GitHub Pages に公開する。
テストが落ちたらそこで止まるので、壊れたものは公開されない。

- 配信は静的ファイルのみ。サーバーもAPIキーも使わない。
- `vite.config.ts` の `base: './'` で相対パス出力にしてあるので、
  `/howa-no-tane/` のようなサブディレクトリでも、独自ドメイン直下でも動く。
- 初回のみ、リポジトリの Settings → Pages で Source が
  **GitHub Actions** になっていることを確認する（ワークフローが自動で有効化を試みる）。
- Vercel や Cloudflare Pages に載せる場合は、ビルド `npm run build` / 出力 `dist` を指定すればよい
  （`vercel.json` は SPA 用の rewrite を入れてある）。
