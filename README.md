# 法話の種

日常の気持ちを入口に、法話の切り口をまとめて出す下ごしらえ帳。

**公開先: https://aokko-aaa.github.io/howa-no-tane/**

## つくりの考え方

教義から降りていくのではなく、**一般の人が実際に立ち止まる場面**（既読がつかない、同級生の新築、免許返納…）から始めて、そこから仏教へ渡す。
同じ気持ちから **18通りの切り口** を回して出すので、「その話はもう何度も聞いた」となりにくい入口を探せる。

既定は **真宗大谷派を優先**（`tradition: 'otani'`）。本願・他力・聞法・報恩を軸に、真宗の切り口（お聖教の一句／御文／歎異抄／私の上に聞く／誤用から入る／報恩講）を先に回し、禅語の素材は後ろへ下げる。結びにはお念仏の一句が添い、語り手向けメモに大谷派の言い回しの注意が入る。
「宗派を問わない」に切り替えると、真宗固有の切り口を外して共通の素材だけで組む。

素材はすべてアプリの中に持っている。外部APIもサーバーも使わない（入力も保存も端末のブラウザの中だけ）。

## 四つの入り方

| タブ | 誰が | 何をする |
| --- | --- | --- |
| **つくる** | お寺の方 | 気持ち・場面から切り口を6通り出す。〈素材を指定して探す〉で「この言葉で」「この一句で」「この切り口で」と名指しもできる |
| **話題から** | お寺の方 | いま流れているニュースの見出しを、法話の入口に変える |
| **たどる** | どなたでも | 三つ選ぶだけで、今の気持ちに合う話がひとつ出る。仏教語を知らなくても選べる |
| **ネタ帳 / ことば** | 共通 | 保存とメモ、仏教語・お聖教・日常語・喩え話・大谷派の言い回しを引く |

### 話題から（ニュース）について

公開RSS（NHK 主要・Google ニュース）の見出しを、24種の「話題の型」
（値上げ／災害／炎上／謝罪会見／介護 など）に当てて切り口にする。

**取得はブラウザではなく、公開のたびにサーバー側（GitHub Actions）で行う。**
ブラウザから直接ニュースサイトを読むことは CORS でできず、公開の中継サービスは実際に止まっていて
当てにならなかったため、`scripts/fetch-news.mjs` が `public/news.json` を書き出し、
アプリは自分と同じ場所にあるその1ファイルを読むだけにしてある。第三者のサービスを経由しない。

見出しの新しさは公開の間隔まで。`deploy.yml` に3時間ごとの `schedule` を入れて公開し直している
（GitHub の仕様で、リポジトリに60日間動きがないと定期実行は止まる。動かすには手動実行か push）。
取得に失敗しても空の `news.json` を書いてビルドは通す。貼り付け欄はいつでも使える。

実際の出来事を扱うため、生成した案には必ず
「当事者が聴衆にいる前提で。実名や詳細に踏み込まない、断罪しない、意味づけを急がない」
という心得が付き、災害・事件・訃報・政治などの型には個別の注意も付く。

### たどる（チャート）について

きもち → ことがら → どうしたい、の三択で一つの読み物にたどり着く。
出力は法話の下書きではなく、そのまま読める文章（`src/lib/reading.ts`）。
一つ目の「きもち」を二つ目より強く効かせて、悲しみの相談に子育ての場面が出るようなズレを避けている。

## 素材の構造

| ファイル | 中身 | 役割 |
| --- | --- | --- |
| `src/data/emotions.ts` | 気持ち 28種 | 一般の人が自分の言葉で選ぶ入口 |
| `src/data/concepts.ts` | 仏教語・教義 46種 | `misread`（世間の受け取り）→ `pivot`（仏教から見たズレ）の対で持つ |
| `src/data/stories.ts` | 喩え・逸話 27種 | そのまま語れる長さの要約と使いどころ |
| `src/data/words.ts` | 日常語になった仏教語 27種 | 我慢・億劫・大丈夫…「入口を広く」する主力 |
| `src/data/modern.ts` | 現代の場面 44種 | 法話の一行目に使う語り出し |
| `src/data/occasions.ts` | 年中行事 14種 | 季節に寄せる切り口の素材 |
| `src/data/angles.ts` | 切り口 18種・場面 6種 | 裏返し／語源ひらき／逆説／こじつけ全開＋真宗の6種 |
| `src/data/shinshu/concepts.ts` | 真宗の教義 24種 | 本願・他力本願・二種深信・摂取不捨・平生業成・還相回向 など |
| `src/data/shinshu/phrases.ts` | お聖教の一句 21種 | 正信偈・和讃・歎異抄・御文・大経。法話の頭に置く |
| `src/data/shinshu/stories.ts` | 祖師・近代の話 13種 | 六角堂・越後配流・歎異抄第九条・白骨の御文・清沢満之 など |
| `src/data/shinshu/manners.ts` | 言い回しの注意 13種 | ご冥福／追善供養／戒名／御霊前／焼香の回数 などの言い換え |
| `src/data/shinshu/words.ts` | 真宗の日常語 6種 | 他力本願・往生・ご縁・ようこそ・あなかしこ |
| `src/data/shinshu/occasions.ts` | 真宗の年中行事 11種 | 修正会・永代経・御正忌報恩講・お取り越し など |
| `src/data/news.ts` | 話題の型 24種 | 見出しを受け止めて、どこを見るかと扱いの注意を持つ |
| `src/data/paths.ts` | チャートの選択肢 | 仏教語を使わずに選べる三択 |

素材を足すときは、同じ形で配列に追記するだけでよい。
`npm test` が、感情タグの実在・idの重複・どの気持ちにも素材が揃っているかを見ている。

## 出力

- **法事・月参り・法話会**：入口 → ひっかかり → 仏教のことば → 視座のズレ → 落とし込み → 結び ＋ 語り手向けの演出メモ
- **掲示板・SNS**：一行の案3つ ＋ 短文 ＋ 聞かれたときの仕込み

カードは**要点（箇条書き）**で出る。素材を名詞で並べてあるので、6案を見比べるときに読み下さなくてよい。
〈話す形〉に切り替えると、そのまま語れる文章になる。

コピーは3種類。**要点**（箇条書きと出典）／**下書き**（見出し・出典・演出メモ込み、推敲用）／
**通し原稿**（そのまま読める形。語り手向けメモは外れる）。

## 出典の扱い

出典は通称で記している。**人前で語る前に原典を確認すること**を前提にしている。
語源や逸話に諸説あるもの（諦める、油断、白隠「そうか」、妙好人の逸話など）はカードの「語る前に確認」に出る。

真宗大谷派の作法・呼び方（位牌と法名軸、焼香の回数、御文と御文章、盆の勤め方、帰敬式の案内など）は
**地域と寺によって実際の扱いに幅がある**。アプリは由来として示すだけなので、自坊の実際に合わせて語ること。
「ことば」タブの〈大谷派の言い回し〉は、門徒さんの習慣を否定するための材料ではない。

## 開発

```sh
npm install
npm run dev        # 開発サーバー
npm test           # データとネタ生成のテスト
npm run typecheck
npm run build      # dist/ に静的ファイル
```

## デプロイ

`main` に push すると GitHub Actions（`.github/workflows/deploy.yml`）が
typecheck → test → build を通し、`dist/` を GitHub Pages に公開する。
テストが落ちたらそこで止まるので、壊れたものは公開されない。

- 配信は静的ファイルのみ。サーバーもAPIキーも使わない。
- `vite.config.ts` の `base: './'` で相対パス出力にしてあるので、
  `/howa-no-tane/` のようなサブディレクトリでも、独自ドメイン直下でも動く。
- 初回のみ、リポジトリの Settings → Pages で Source が
  **GitHub Actions** になっていることを確認する（ワークフローが自動で有効化を試みる）。
- Vercel や Cloudflare Pages に載せる場合は、ビルド `npm run build` / 出力 `dist` を指定すればよい
  （`vercel.json` は SPA 用の rewrite を入れてある）。
